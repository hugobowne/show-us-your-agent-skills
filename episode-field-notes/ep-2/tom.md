# Tomasz Tunguz - Episode 2 field notes

Tomasz Tunguz is a venture capitalist at [Theory Ventures](https://theoryvc.com/team-members/tomasz-tunguz) who works with Bryan Bischof and has spent much of his career around data and data infrastructure companies. In Episode 2, he runs agents as parallel local workers: give them enough context, keep the harness thin, use skills for repeatable analysis, and decide when local models are good enough to beat cloud latency. The repo captures that local-model setup as the [`local-first-agents`](https://github.com/hugobowne/show-us-your-agent-skills/tree/main/workflows/local-first-agents) workflow.

He says *"the great power of agents is parallelization"* [\[01:49:36\]](https://youtube.com/live/l37PR-OkYKA?t=6576), then shows his local setup. Tomasz runs [Pi](https://pi.dev/) with [Qwen 3.6 35B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B), demos a public-company analysis skill for [Figma](https://investor.figma.com/OVERVIEW/DEFAULT.ASPX) earnings, talks through memory and security gaps, and switches to cloud models only for large coding problems or a model-specific strength such as creative writing.

Tomasz can demo a local model producing an earnings deck in minutes, then admit the same day he spent 45 minutes on macOS accessibility permissions for a dictation app. Agents expand the amount of work he can parallelize, but he still has to decide where knowledge lives, which package installs are safe, and when a harness is adding too much context.

## On working with agents

### What he loves: parallel work with enough context and planning

Tomasz answers the first question with a joke about Bryan and agents as different kinds of minds: *"one is a cellular mind, and the other one is a silicon mind"* [\[01:49:24\]](https://youtube.com/live/l37PR-OkYKA?t=6564). His serious answer is that agents become valuable when they can run in parallel without creating coordination drag.

Parallel agents need enough context and planning to save time: *"in order to take advantage of that, you really have to think differently about how do you equip parallel processes with enough context and enough planning in the workflows that they actually save you time"* [\[01:49:39\]](https://youtube.com/live/l37PR-OkYKA?t=6579).

### What he finds most frustrating: agents act intelligent and then forget

Tomasz's frustration is memory. Agents demonstrate high capability, then lose the thread across tabs, skills, plugins, and QMD. He says, *"they demonstrate such a level of intelligence and then they forget"* [\[01:52:20\]](https://youtube.com/live/l37PR-OkYKA?t=6740).

When he switches across multiple tabs, he has to remember what each agent is doing, then decide where memory should live: *"plugins, skills, and then QMD. They don't live cleanly. They don't have clean demarcated lines of what goes in which"* [\[01:52:59\]](https://youtube.com/live/l37PR-OkYKA?t=6779).

### What would worry him if agent conversations leaked: basic programming asks

Tomasz says the embarrassing part would be the low-level programming problems he hands to agents. *"I would be most embarrassed by the very basic programming problems I ask my agents to solve for me"* [\[01:59:02\]](https://youtube.com/live/l37PR-OkYKA?t=7142).

His example is a local Super Whisper or WhisperFlow competitor. He spent 45 minutes getting macOS accessibility permissions right so the app could paste text into another app. Signing the app properly should have fixed it quickly: *"if I knew any kind of macOS program I could have solved that in 30 seconds"* [\[01:59:41\]](https://youtube.com/live/l37PR-OkYKA?t=7181).

## Workflows

### Equip parallel agents with enough context to save time

Tomasz treats parallelization as an orchestration problem. Agents can run many threads of work, but each worker needs enough context and planning to avoid wasting the user's time: *"equip parallel processes with enough context and enough planning in the workflows that they actually save you time"* [\[01:49:47\]](https://youtube.com/live/l37PR-OkYKA?t=6587).

Hugo compares agent parallelization to Amish barn-raising, where many people coordinate physical work at once. Tomasz extends the joke into operations research: *"I would love to see them pack a box in a bin. Have they solved the bin packing problem?"* [\[01:50:38\]](https://youtube.com/live/l37PR-OkYKA?t=6638).

### Generate public-company earnings briefings

Tomasz demos a skill he uses to analyze public companies after earnings. For Figma, the skill pulls CSVs from a data source, places them in a folder, finds the earnings transcript with [Exa](https://exa.ai/), uses R libraries to create charts, and assembles an HTML presentation. He summarizes the output as *"a single presentation that walks me through exactly what's happened in Figma"* [\[02:01:33\]](https://youtube.com/live/l37PR-OkYKA?t=7293).

He also runs the workflow as a recurring briefing: *"I can run this on a launch daemon on my computer, so every morning it checks, okay, which publicly traded companies have announced earnings"* [\[02:03:30\]](https://youtube.com/live/l37PR-OkYKA?t=7410).

The Figma presentation worked well enough to brief the business, but Tomasz calls out rendering bugs in the charts. *"There are some bugs, clearly,"* he says as two charts fail to render properly [\[02:03:11\]](https://youtube.com/live/l37PR-OkYKA?t=7391). His next step is to feed that back into *"the skill to continuously improve."* [\[02:03:17\]](https://youtube.com/live/l37PR-OkYKA?t=7397).

### Use local models first, then switch to cloud for hard edges

Tomasz runs most of his workflow locally in Pi with Qwen 3.6 35B. On a Mac M5, he says he gets *"120 to 140 tokens per second with a 256K context window"* [\[02:07:42\]](https://youtube.com/live/l37PR-OkYKA?t=7662). He shows Pi answering weather and Hacker News questions quickly, then explains that the thin terminal harness and low context overhead are part of why it feels interactive.

Tomasz uses local models for convenience: *"I do it for convenience"* [\[02:08:43\]](https://youtube.com/live/l37PR-OkYKA?t=7723). They keep working on a plane, reduce latency, and let him paste secrets without sending them elsewhere. He switches to cloud models for *"large-scale coding challenges, particularly multi-files or rearchitectures or bugs that simply can't be solved"* [\[02:09:17\]](https://youtube.com/live/l37PR-OkYKA?t=7757), or when a cloud model has a specific strength, such as Kimi K26 for creative writing.

### Resume interrupted work from saved Pi sessions

Tomasz likes that Pi passively saves sessions, because saved local history can become a memory mechanism. His example is asking the model to search the last six hours of Pi work and resume the right task: *"Can you run ripgrep over the Pi sessions for the last six hours and find where we were and then pick it up"* [\[02:13:11\]](https://youtube.com/live/l37PR-OkYKA?t=7991).

Session history bridges interruptions without requiring a heavier long-term memory system.

[Pi](https://pi.dev/) is Tomasz's local harness. He starts the demo by saying, *"I live in Pi and I run local models"* [\[02:00:37\]](https://youtube.com/live/l37PR-OkYKA?t=7237). Later, he explains that Pi works for him because its terminal UX is thin, its context overhead is small, and it can still act effectively with a minimal setup.

He shows Pi doing basic tool work, including weather and Hacker News queries, and he values its saved sessions. The thin harness preserves latency: *"You can literally strip almost to the bone and it'll still work"* [\[02:12:20\]](https://youtube.com/live/l37PR-OkYKA?t=7940).

### Qwen 3.6 35B

[Qwen 3.6 35B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) is Tomasz's preferred local model for the Pi demo. He says, *"I'm using Qwen 3.6 35 billion"* [\[02:05:51\]](https://youtube.com/live/l37PR-OkYKA?t=7551).

### Local dictation app

Tomasz built a local dictation app as an alternative to Super Whisper or WhisperFlow. He describes it first as a leak-embarrassment example, then gives the stack later in the model discussion.

The tool uses Parakeet for ASR, SwiftLLM for local inference, and Gemma 4 e4B for post-processing. The goal is latency: *"you can reduce your latency from 3,000 milliseconds to 300 milliseconds running locally"* [\[02:06:26\]](https://youtube.com/live/l37PR-OkYKA?t=7586).

### Parakeet

[Parakeet](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v2) is the local ASR model in Tomasz's dictation tool. He says the Super Whisper alternative *"uses Parakeet locally running on SwiftLLM"* [\[02:06:13\]](https://youtube.com/live/l37PR-OkYKA?t=7573).

It handles the speech-recognition side of the local workflow.

### SwiftLLM

SwiftLLM is the local inference layer in the dictation tool. Tomasz says that putting the stack into SwiftLLM cuts latency for ASR and prompt-based post-processing [\[02:06:23\]](https://youtube.com/live/l37PR-OkYKA?t=7583).

## Principles and explainers

### Memory needs the right granularity and update rules

Tomasz explains that memory is not only a storage problem. Agents may update some parts of memory but leave stale instructions behind: *"they might leave relics of previous memories in the past"* [\[01:53:50\]](https://youtube.com/live/l37PR-OkYKA?t=6830).

He does not have a settled model for memory granularity. Human teams can often tell what belongs at which level, but coding a memory that is useful to an agent is still unclear to him.

### Harnesses grow around the model as the work grows

Tomasz does not treat the model as the whole agent system. Even with Pi, which he calls a simple harness, he keeps adding surrounding code and context as he asks more of it. *"Even with the simplest version of a harness, you just find yourself or I find myself just adding more and more around"* [\[01:55:13\]](https://youtube.com/live/l37PR-OkYKA?t=6913).

He has to decide what belongs in skills, plugins, QMD, AGENTS.md, MCPs, and session lookup. The same memory or security rule could belong in several agent-facing surfaces.

### Bring-your-own-agent creates enterprise security and IP questions

Tomasz compares future agent adoption to bring-your-own-device adoption. A new graduate may have spent years embedding their education into an agent and need it at work to be productive. The CISO's question is blunt: *"What is this thing doing?"* [\[01:57:00\]](https://youtube.com/live/l37PR-OkYKA?t=7020).

He thinks work and personal agents will probably need separation because securing a personal agent is hard. That raises ownership questions inside a company: whether the agent becomes enterprise IP, whether the employee keeps rights, or whether it needs to be licensed.

### Local models change the latency and privacy budget

Tomasz makes a concrete local-model argument with numbers. On a Mac M5, he says Qwen 35B can run at *"120 to 140 tokens per second with a 256K context window"* [\[02:07:42\]](https://youtube.com/live/l37PR-OkYKA?t=7662).

Cloud tools feel slower next to that local speed. Local models also let him paste secrets without sending data elsewhere, and they continue working on planes or other offline situations.

### Tool-calling reliability varies by model and inference engine

Tomasz likes Qwen because it can do sophisticated single-file coding and *"almost any single tool calling that you want"* [\[02:06:54\]](https://youtube.com/live/l37PR-OkYKA?t=7614). His Gemma experience has been different: long-term tool following was hard, and parser support in inference engines was broken at first.

Local models are strong enough to be primary tools for some workflows, but model choice and inference engine support still determine whether an agent can follow tools over time.

### Thin harnesses preserve interactive speed

Tomasz warns that a large system prompt can erase the local-model speed advantage. Some harnesses start with *"25 or 40,000 tokens as part of the system prompt"* [\[02:12:07\]](https://youtube.com/live/l37PR-OkYKA?t=7927), which makes it hard to keep tokens per second feeling interactive.

Pi's thin setup is why he likes it. The local model has a large context window, but the harness should avoid filling it before the user even starts.

### HTML is a strong agent output format, but private sharing still hurts

Tomasz agrees with Hugo that agents are rediscovering HTML as a presentation format. His own Figma briefing is an HTML artifact. He likes the medium but names the operational problem: *"It's really hard to share privately, which is kind of a bummer, so you have to generate a PDF"* [\[02:02:20\]](https://youtube.com/live/l37PR-OkYKA?t=7340).

The PDF conversion is still imperfect in his workflow because margins are not managed properly.

### Supply-chain policy needs a durable home in the agent system

The NPM-package moment turns security into an instruction-placement problem. Tomasz knows the heuristic he wants, avoid very new packages, but he does not know where to put that rule so agents consistently obey it.

He asks the architecture question directly: *"Should that live within a skill? Does that live within a plugin? Does that live within QMD? Does it live in agents.md?"* [\[02:04:57\]](https://youtube.com/live/l37PR-OkYKA?t=7497).

### Local inference is getting faster through systems work

Tomasz argues that local models are becoming more viable because the serving stack is improving. Inference servers are stronger, middleware is moving away from slower paths, quantization is usable, and draft models help.

At that speed, *"you're generating 60 to 100, 120 tokens per second. You're not waiting"* [\[02:10:38\]](https://youtube.com/live/l37PR-OkYKA?t=7838).
